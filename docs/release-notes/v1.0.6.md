# DSH CCGUI v1.0.6 版本记录

**发布日期**：2026-11-12
**对比**：v1.0.5 → v1.0.6（20 个提交）

---

## ✨ 新功能

### CLI 自己的模式（`9058adb`、`ff13015`）

- **模式按钮**：CLI 名字右边新增「CLI 模式」按钮，列的是该 CLI 通过 ACP `category: "mode"` 报出的模式（比如 accept edits、plan），option id 和名字原样使用，不翻译成 DSH 的权限预设。CLI 一个模式都没报时按钮不出现。
- **生效时机**：CLI 进程在运行时选中当场生效；进程还没起来时先记下，随下一条消息一起发出，按钮上标注「下一条消息发送时生效」，CLI 收下之后提示自己消失。选择记在 CLI 路由上并写进模型缓存，重启后还在，切换 CLI 也不会把上一个 CLI 的模式带过来。
- **和访问模式的分工**：按钮出现时输入框里不再显示 DSH 的访问模式，需要时仍可用 `/permission` 查看和切换。CLI 报了什么模式决定它问不问，访问模式只决定它问了之后由谁答。CLI 没报模式时访问模式照常显示。
- **不接受的选择**：CLI 不收这个模式时，消息照常发出，回复开头会说明没切成、这条消息按哪个模式运行，这次选择随即作废，不会在之后的消息里重试。
- **接口**：新增 `POST /dsh-ccgui/modes`，与 git 路由同一套鉴权，只报告状态和转发 id，错误按 400 返回，不暴露内部信息。

### 「EXP 自动审查」可以在 CLI 会话里用（`09faba8`、`566d46d`）

- 审查请求转给一个独立、无状态的模型提供方，不再被当成用户输入塞进 CLI 的会话历史；Auto 和完全权限预设也因此不再为每次审查请求弹审批。
- 路由必须在插件配置里指定：`reviewProvider` 必填且不能是 CLI（否则会绕回这个适配器），`reviewModel` 可选，不填就用该提供方的第一个模型。插件不会替你挑，因为审查请求带着对话内容，自动挑选会把代码和费用交给你没选过的提供方；没配置时会提示去配置或改用其它访问模式。
- CLI 模型的推理等级不会带过去，审查模型按自己的默认等级运行。摘要、压缩等其它带 `purpose` 的辅助请求仍然拒绝。
- 审查模型拒绝一次工具调用时，会连同该调用悬着的 ACP 权限请求一起拒绝。CLI 如果是先执行再上报，这次拒绝撤不回已经发生的改动。

### 模型菜单按厂商显示图标和倍率（`4b5d9b8`、`6b75556`、`09faba8`、`7ce2a37`）

- **厂商图标**：模型行前的图标改成模型厂商的图标。新认 Hunyuan（Hy3 / Hy4）、智谱 GLM、MiniMax、阶跃 StepFun 和小米 MiMo；CodeBuddy 这类聚合 CLI 里，GLM、MiniMax 这些模型不再统一显示 CodeBuddy 的紫色 logo，那个 logo 说的是 CLI，不是模型。
- **认不出用问号**：模型厂商无法识别的，用中性的问号图标占位，不借用任何品牌，也不拿 WorkBuddy 的 app 图标代替。Space-Bunny 这类没有公开确认厂商的匿名模型也一样。
- **倍率小字**：模型名保持 CLI 给的原样，右侧小字显示 CLI 报的简短描述，比如 CodeBuddy 的 `x0.29 credits`，免费档、付费档和其它模型的消耗倍率都能在菜单里看到。只有带数字、不超过 20 个字符、不像句子的描述才显示，宣传语一类的长句不上屏；这些描述也会写进模型缓存，重启后仍在。
- **同名模型**：名字相同的免费档和付费档靠倍率小字区分，不再被当成重复项过滤掉；倍率也区分不了时，才在名字后面补上 id。会话里显示的当前模型名不带倍率。

### 原生会话保留 DSH 自己的模型菜单（`ff9e39b`、`0028d96`）

- 不再接管非 CLI 会话的模型座位：DSH 自己的模型菜单、推理等级和智能体团队协作开关都留在原位。
- 插件只把原生菜单里其他 CLI 的分组隐藏掉，因为这些会话本来也切不过去；DSH 改了菜单结构时这些分组会重新出现，不影响使用。
- CLI 会话仍然使用插件自己的模型菜单，只列当前 CLI 的模型。

## 🐛 问题修复

### CLI 拒绝时说明原因（`d80a508`、`de47a06`、`5cb28fa`、`6ff04c3`）

- ACP 的 `session/prompt` 响应没有错误字段，拒绝的原因只可能在本轮输出的文本里，或者根本没输出。现在按顺序找：本轮输出的文本（超过 400 字保留末尾）→ 回答 `_meta` 里的具名原因字段 → 这一轮写到 stderr 的最后两行。哪里都找不到时仍写「未说明原因」。
- CodeBuddy 把 JSON-RPC 错误字符串化后放在 `codebuddy.ai/errorMessage`；现在能识别这个字段（以及 `errorMessage`、`codebuddy.ai/error` 和通用的 `error` / `message` / `reason`），解析出里面真正解释问题的那句，中文说明优先于「Quota exceeded: 429」这类英文模板。错误保留开头而不是结尾，请求 id 不显示。
- 模型的思考内容和插件自己插入的提示（模式没切成、思考等级被沿用、新会话）不算原因，不会被当成拒绝理由。
- 整包的 `_meta` JSON、trace 头、JSON 日志行一律不显示，宁可回到「未说明原因」；`[ERROR] …` 这类带级别或时间的日志行保留。
- stderr 按轮读取：记下每条 prompt 开始时的字节位置，只读这一轮写的内容，不会拿上一轮的日志解释后面的拒绝。

### 完全权限下 CLI 提问不再被静默拒绝（`46e8f6f`）

- DSH 在「完全权限」下记录 `approval/policy: never`，审批服务对任何请求都直接回 `rejected`。CLI 也走同一个服务，于是它的 `Always Ask` 变成静默拒绝：改动消失，屏幕上连审批卡片都没有。
- 现在只在 CLI 提问期间把会话临时切到「询问」，问完恢复原设置。两次切换都写成会话事件，会话日志里看得到；只有 CLI 会走这个桥，DSH 自己跑的会话不受影响；读不到当前策略的旧版 DSH 保持原有行为。

### 模式相关的小问题

- 一个会话里切换模式，不再让还没开始的空白会话显示那个模式：只有新 CLI 会话的报告会进目录，空白会话显示的是 CLI 新启动时的默认值（`566d46d`）。
- 「下一条消息发送时生效」的提示在 CLI 收下选择后自动清除，不用重新打开菜单（`0c83320`）。
- 模式列表的读取接口按会话缓存，不再随着每次渲染重新读一遍（`7eb4e7a`）。
